1. **Role connection (0:00–0:20)**
   - Show the queue.
   - Say: “I took Convex’s GTM Engineer brief literally: find when a team is getting serious, surface the right moment, and route it to the right play or person.”
2. **Early momentum (0:20–0:50)**
   - Run Sandbox option 1: Growing team.
   - Explain that production use, multiple people, and sustained usage create an observation—not premature outreach.
3. **Evidence brief (0:50–1:20)**
   - Open the team review.
   - Point to the three plain-language facts under “Why this is in your queue.”
4. **Threshold crossing (1:20–1:50)**
   - Run Sandbox option 3: Growing team asks a buying question.
   - Show the same team case changing route and owner without duplication.
5. **Human handoff (1:50–2:15)**
   - Select Prepare response.
   - Show the response brief and the delivery preview. Say that it is test-only and no message is sent.
6. **Operational proof (2:15–2:35)**
   - Show the terminal proof or local Convex data view.
   - Mention 24 fixtures, duplicate races, outage/recovery, and 10× workload.
7. **Boundary (2:35–2:50)**
   - State that all records are synthetic and real deployment would require approved sources, privacy review, recipient configuration, and authorization.

## Recording setup

- Run `npm run verify:demo-reset` first.
- Start the local Convex backend and app.
- Use only the labelled sandbox options.
- Do not show credentials, local database files, or unrelated records.
- Delivery cards are previews, not Slack/email sends.
