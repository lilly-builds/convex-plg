# Short Introduction

I built a synthetic, policy-driven Convex prototype for the core GTM Engineer problem: recognize serious team momentum, surface the right moment, and route an explainable human next step.

The prototype uses labelled fake records only. It does not claim access to Convex customer data or internal cross-customer APIs, and it does not send Slack or email. The local Convex proof covers the decision policy, upgrades, duplicate events, delivery failure and recovery, and a 10× workload.

A real rollout would need approved source access, clear data-use and retention rules, named owners, recipient configuration, and explicit authorization before any live delivery.
